# gsm.safety v1.4.0 (Upcoming)

Every chart safety.viz draws can now be drawn from R. The last two renderers without an R binding — the Kaplan-Meier time-to-event display and the participant profile — ship as widgets in this release, so the deferral list that has carried them since v1.2.0 is empty.

Both were held back by the same thing, and it was never the JavaScript: each needs a second data frame, and the widget contract carried one. That contract is now general — a widget reads the datasets its data contract names, rather than assuming there is one — so the next renderer that arrives with two frames needs no change to the machinery.

## What's new

- **`Widget_TimeToEvent()` — Kaplan-Meier curves for an endpoint you compose while looking at it.** There is no pre-derived time-to-event dataset, because the endpoint is not fixed in advance: multiselect filters over the adverse events decide which events qualify — every treatment-emergent event by default, and one click away the serious-only endpoint or a body-system basket. The module takes each participant's first qualifying event, censors everyone else at their own follow-up-end day, and draws the product-limit estimator with Greenwood log-log pointwise 95% bands, censor marks, and the at-risk and cumulative-event tables beneath the axis. Cumulative incidence is the default orientation because that is the safety convention; survival is a control away. Takes two frames: the events, and the population that is the denominator. ([#71](https://github.com/jwildfire/gsm.safety/issues/71), hub [obot.roadmap#165](https://github.com/jwildfire/obot.roadmap/issues/165))
- **`Widget_ParticipantProfile()` — the participant drill-down as a report of its own.** A demographics header, a labs-over-time spaghetti standardized to multiples of the upper limit of normal or of baseline, adverse-event tracks drawn on that same study-day axis so a rash and a bilirubin rise line up, and a measure table whose sparklines expand into an inset. A cohort of more than one is ranked worst-first and stepped through. The profile already existed inside three charts as a rail beside the chart; what it lacked was a standalone surface for a report that already knows its cohort — a per-participant appendix, a narrative for a set of flagged participants. Name the cohort with `chrParticipants`; without one the profile waits for a selection event that a static report never sends. ([#71](https://github.com/jwildfire/gsm.safety/issues/71))
- **`ExampleData("adsl")`** — one row per participant with their treatment arm, follow-up-end study day and end-of-study status. The population denominator `Widget_TimeToEvent()` censors against, vendored from the same safety.viz demo data as the other four sets.
- **Report workflows and example pages for both**, `time_to_event.yaml` and `participant_profile.yaml`, each with its runner script and its live page in the gallery.

## Worth knowing

- **The design question this release was waiting on turned out to be two-thirds already answered.** The requirement asked whether the participant profile's R surface should be a standalone widget, a compound widget hosting a chart plus a rail, or profile-enabled variants of the lab widgets. The vendored bundle decides it: the compound mount cannot be reached from R at all, because safety.viz does not export `profileRail` on its public object; and the profile-enabled lab widgets already shipped in v1.2.0 — `Widget_HepExplorer()`, `Widget_Histogram()` and `Widget_OutlierExplorer()` mount the rail from their `profile` setting, on by default in the first. The standalone surface was the only real gap, and it is what this release adds.
- **A widget that loads nothing looks exactly like one that works, and now something says so.** A binding that constructs its renderer and never hands it data raises no console error, still emits its element, still ships the bundle, and still carries every data value in the page — measured on a deliberately broken copy of a working widget, which no assertion in the suite could tell apart from the real one. A new test asserts every binding both constructs *and* feeds its module, and it was proven in both directions: red with the feed call removed, green with it restored.
- **The two deferral lists can no longer disagree.** `.github/parity-allowlist.yaml` and the test's own deferral list are now asserted equal, and every allowlist entry must still name a filed requirement. A renderer dropped from one file and left in the other used to keep reporting itself as deferred after it shipped.
- **The eleven existing widgets are byte-for-byte unchanged in what they send the browser.** The generalized payload builder returns exactly the payload it did before for any contract that names a single dataset.
- **Five workflows had been failing before they started, and two of them are the qualification checks.** `gsm.utils` and `qcthat` moved from the `Gilead-BioStats` organisation to `Gilead-Public` on 2026-08-04. GitHub redirects the old name for an action called from a step, which is why `R-CMD-check` never noticed, but not for a reusable workflow called from a job, which is resolved when the workflow file is parsed. `pkgdown-all`, `test-coverage`, `qcthat` and `workflow-template-check` had failed every run since with zero jobs, and `Release` failed the same way on v1.1.0. A run that fails that early raises no check run at all, so none of it appeared on a pull request: PR [#68](https://github.com/jwildfire/gsm.safety/pull/68), the v1.2.0 candidate, showed six checks and six passes while four workflows were failing against the same commit. Every workflow file is now the current upstream template verbatim. ([#55](https://github.com/jwildfire/gsm.safety/issues/55))

# gsm.safety v1.3.0 (Upcoming)

Twelve of the thirteen census metrics, and every clinical figure the safety overview leads with is now a number the pipeline computes, publishes beside its denominator and can be checked on its own — plus the report that reads them, and `SafetyCensus()` rebuilt on top of both. All four steps of the SafetyCensus rebuild ([obot.roadmap#274](https://github.com/jwildfire/obot.roadmap/issues/274), design [D0023](https://jwildfire.github.io/obot.roadmap/reports/decisions/2026-08-20-safety-census-rebuild/) approved 2026-08-20).

The published figures move in this release, and that is the release rather than a footnote to it. A safety tool that quietly corrected a death count would be worse than one that never had the bug, so every figure that moved is named below with what it was wrong about, and every figure that left the payload is named with why nothing publishes it yet.

The death count came first because it is the number the review was written about. The other eleven follow it into the same machinery: the same declared columns, the same guard, the same anchor to the enrolled population, and the same empty flag. Four of them report a different number than `SafetyCensus()` does today, and each of the four was wrong for a reason named below.

Data completeness, the thirteenth, is not here. Why is under *Worth knowing*.

The report is the third step, and its whole job is to read. It presents the figures the metrics published, beside the denominators the metrics published, under the labels the metric definitions carry — and it computes nothing of its own, so there is no second counting lane and no way for the census to disagree with the rest of the package about the same study. What each metric published is printed verbatim at the foot of the page, so every presentation on it can be checked against its source without leaving the page.

## The figures that move, and why they were wrong

| Figure | Before v1.3.0 | Now | Why it was wrong |
|---|---|---|---|
| Deaths | 4 | **13** | matched the text of a discontinuation reason, never read the death domain, and counted participants who were never enrolled |
| Randomised to an arm | *blank* | **577** | read a treatment-arm column no standard domain carries, so it comes out blank on every study but the demo |
| Received study drug | 744 | **762** | inferred dosing from treatment time being greater than zero, which drops everyone dosed and stopped inside a day and reports zero when the column is absent |
| Participants with a disposition record | 100 | **76** | counted every identifier in the disposition domain, enrolled or not — the defect shape the review caught elsewhere as five completers in a four-person study |
| Participants with an ECG | *blank* | *absent, and it says so* | reported a blank where the domain is missing instead of stopping and saying so |

Measured on the ecosystem's bundled study `AA-AA-000-0000` at `gsm.core` 1.3.1. Enrolled participants (762), participants with a lab result (598) and participants with a reported adverse event (661) are unchanged — they were already right, and they are metrics now so that stays checkable. Person-years on study and on treatment are unchanged as quantities: the metrics publish 26,754 and 10,761 participant-days, and the report is what divides by 365.25.

Every one of these figures was measured twice, by two routes that share no code, and recorded in `inst/qualification/census-metrics-qualification.md` with a reproducer that exits non-zero if the routes ever disagree.

### The death count, in detail

`SafetyCensus()` reports four deaths on the ecosystem's bundled study. It reaches that number by matching the text of a discontinuation reason in the study-completion domain, which on that study names four participants — three of them enrolled and one never enrolled — and it counts all four because it anchors nothing to the enrolled population. It never reads the study's death domain at all, and that domain names twelve more.

The new `saf0004` metric reports 13 deaths of 762 enrolled participants on the same study — a threefold correction to a published clinical figure, and the entire reason this rebuild exists.

> Corrected 2026-08-21 while building step two. This section first said the function reports **one** death and called the correction thirteenfold. One is what it reported on `gsm.core` 1.2.0, the version D0023 was written against; on 1.3.1 the same study gives that discontinuation reason to four participants and the function reports **four**. The metric's own figure of 13 was re-measured and is unchanged. Evidence in `inst/qualification/census-metrics-qualification.md`.

Three numbers, kept apart, because they answer different questions:

- **16** — the two death sources combined: 12 participants with a death record, plus 4 whose discontinuation reason is `Death`, with no overlap between them. This is `gsm.mapping`'s union, and it is correct for what it names.
- **13** — what the metric publishes. Three of the sixteen have `enrollyn = "N"`: never enrolled, no enrolment date, no time on study. Every gsm metric anchors its count to the enrolled population, so publishing 16 over a denominator of 762 would put three people in the numerator who are not in the denominator — the defect shape the review caught elsewhere as five completers in a four-person study. The anchor wins; the difference is three identifiable participants, named in `inst/qualification/death-count-qualification.md` rather than absorbed.
- **4** — what `SafetyCensus()` returned before this release, on the same study. It is history now: step four ([#66](https://github.com/jwildfire/gsm.safety/issues/66)) removed the arithmetic that produced it, and the function publishes the metric's 13. The figure that changed is a published clinical figure on a safety page, which is why it leads these notes.

The count is qualified rather than asserted: it is measured twice on the same study by two routes that share no code — the death records read directly with base R, and the standard mapping run through the workflow — and both land on 13. The evidence, the versions and the reproducer are recorded in `inst/qualification/death-count-qualification.md` and run in the suite as `tests/testthat/test-qualification-death-count.R`.

## What left the payload, and why nothing publishes it yet

`SafetyCensus()` computes nothing now, so a figure no metric publishes is not in what it returns. Three things a caller saw before this release are gone, and none of them is gone quietly.

| What left | Where it went | Why it is not computed here |
|---|---|---|
| Median days on treatment | nowhere yet — it wants an averaging step in the metric layer ([#61](https://github.com/jwildfire/gsm.safety/issues/61)) | a median computed beside the metrics is a second counting lane whatever table it is computed from, and the second lane is the defect this rebuild exists to remove |
| The per-visit data-coverage table | carried to the thirteenth census metric ([#58](https://github.com/jwildfire/gsm.safety/issues/58)) | `gsm.mapping`'s lab domain carries no visit column under the standard mapping, and the expected count needs a per-visit study day no domain supplies. `Coverage` is returned with its columns and no rows, which its reader already renders as "no visit-level coverage in this snapshot" |
| The disposition states with no metric — `Ongoing`, `Discontinued - <reason>`, `Not in the disposition domain` | `Discontinued - <reason>` wants an enumeration the metric layer cannot declare in advance ([#61](https://github.com/jwildfire/gsm.safety/issues/61)); `Not in the disposition domain` was a subtraction | the reason breakdown was read out of a free-text column and is where the blank-reason defect lived; `Ongoing` was a completion flag nobody had filled in read as a state. `Disposition` now holds the three states the disposition metrics publish: completed, discontinued and died |

And one figure is absent rather than wrong wherever a study does not map the domain behind it. A study with no death domain now reads as not collected for deaths instead of reading a discontinuation reason, with a warning naming `Mapped_Death`. That is the intended behaviour and it has a consequence worth stating plainly: the demo study maps no death domain and no randomisation domain today, so its deaths tile and its randomised tile read as not collected until its mapping phase adds them. Absent is not zero, and it is not a quiet blank either — the pipeline log names the domain that would have produced each figure.

## What's new

- **`saf0004`, a descriptive study-level death count** ([#56](https://github.com/jwildfire/gsm.safety/issues/56)) — counted from `Mapped_Death`, which is `gsm.mapping`'s own union of the death domain and the discontinuation reason, so no clinical definition of death is written in this package. The metric declares every column it reads, counts each participant once however many rows the domain carries for them, and anchors the count to the enrolled population.
- **The metric does not flag, and cannot** ([#56](https://github.com/jwildfire/gsm.safety/issues/56)) — no threshold in its meta, no flagging step in its workflow, nothing amber and nothing red (D0023.3). New exported step `Flag_None()` stands where `gsm.core::Flag()` would and leaves the flag empty, following gsm.kri's `srs0001` site risk score, which has published its rows that way in production throughout. Empty, not zero: a zero would mean measured and found fine. Because the metric carries no threshold it contributes no weights, so gsm.kri's risk-score builder skips it and this figure cannot move a site's risk score.
- **New exported step `Input_Deaths()`** ([#56](https://github.com/jwildfire/gsm.safety/issues/56)) — the numerator behind `saf0004`, and where the three states are kept apart: a study with no death domain, or a death domain missing a declared column, errors; a death domain with no rows at all publishes no figure and warns; a populated death domain marking nobody as died publishes zero. Absent is not empty and empty is not zero — only the last of the three is a measurement.
- **Study level is a setting, not a rewrite** ([#56](https://github.com/jwildfire/gsm.safety/issues/56)) — `GroupLevel` and `GroupCol` are meta values the workflow reads, so moving the metric to site or country level is two lines rather than a second definition (D0023.4).
- **Eleven more descriptive census metrics, `saf0005` through `saf0015`** ([#58](https://github.com/jwildfire/gsm.safety/issues/58)) — enrolled participants, randomised participants, participants dosed, participant-days on study, participant-days on treatment, participants with a lab result, with an ECG, with a reported adverse event, with a disposition record, who completed, and who discontinued. Each declares the exact columns it reads, each carries the same guard, and none of them flags.
- **Two new exported steps behind them, `Input_Participants()` and `Input_ParticipantDays()`** ([#58](https://github.com/jwildfire/gsm.safety/issues/58)) — one counts the participants a domain names, optionally only those whose column matches a value or records anything at all; the other sums a person-time column. Eleven metrics share two steps on purpose: eleven hand-written counting functions are eleven chances to leave out one of the rules, which is the defect class this rebuild exists to remove. The differences between the metrics — which domain, which column, which value — are declared in the definitions, where a reader can check them.
- **Every count is anchored, deduplicated and guarded, and the tests say so for all eleven at once** ([#58](https://github.com/jwildfire/gsm.safety/issues/58)) — one table drives the workflow suite, so every metric is asserted to publish no row when its domain is empty, to be unchanged by a duplicated row, and to ignore a participant identifier that was never enrolled. The column guard is checked in its strongest form: *every* column *every* definition declares is dropped in turn, and the metric has to stop. A column a definition declares but no step reads would be a promise to a reader that nothing keeps, and this is what makes that impossible to leave behind.
- **Participant-days are published as days** ([#58](https://github.com/jwildfire/gsm.safety/issues/58)) — the number actually summed, in the unit the subject domain records. The report presents years and does the division, so the metric stays checkable against the domain it came from. Person-time that was never recorded leaves the total and the denominator together, with a warning naming the participants: missing days are not zero days.
- **Dosing is a recorded first dose** ([#58](https://github.com/jwildfire/gsm.safety/issues/58)) — `saf0007` counts participants with a `firstdosedate`, not participants whose treatment duration is greater than zero. On the bundled study that is 18 more participants, every one of them dosed and stopped inside a day.
- **Randomisation is counted from the randomisation domain** ([#58](https://github.com/jwildfire/gsm.safety/issues/58)) — `saf0006` counts that a participant was randomised without reading what they were randomised to, so the figure stops depending on a treatment-arm column a blinded safety view should not read anyway (and which no standard domain carries).
- **The census report, `inst/workflow/4_modules/safety_census.yaml`** ([#61](https://github.com/jwildfire/gsm.safety/issues/61)) — one report workflow over the census metrics, modelled on the gsm.kri report: the workflow declares the reporting tables it reads and its steps call helper functions, rather than one large function doing the work. It renders a self-contained HTML page — the study's population, its exposure and its follow-up, each figure beside its own denominator — from `Reporting_Results` and `Reporting_Metrics` alone.
- **Four new exported steps, and none of them counts anything** ([#61](https://github.com/jwildfire/gsm.safety/issues/61)) — `Report_CensusFigures()` lays the published figures out in the sections the workflow declares, `Report_CensusCoverage()` reads a data-coverage metric's rows, `Report_CensusProvenance()` records what every metric published verbatim, and `Report_SafetyCensus()` writes the page. None of them takes a study domain as an argument, so none of them could recount a figure even by accident — which is the property the whole rebuild rests on, and the tests check it by feeding the report figures that are deliberately not the study's, and requiring the page to show them.
- **The report presents years and the metrics publish days** ([#61](https://github.com/jwildfire/gsm.safety/issues/61)) — the two person-time metrics are named in the workflow's own settings, along with the days to a year, so the division is a declared presentation rather than a decision buried in code. Both numbers reach the reader: 26,754 participant-days on study appear as 73.2 person-years in the exposure table and as 26,754 in the provenance table below it.
- **Nothing on the page flags** ([#61](https://github.com/jwildfire/gsm.safety/issues/61)) — no flag column, no colour carrying a verdict, no cut-point (D0023.3). A result that arrives carrying a flag is refused rather than presented, because a page that shows no flags would hide a signal rather than describe a study.
- **A metric that published nothing is named, not blanked** ([#61](https://github.com/jwildfire/gsm.safety/issues/61)) — the provenance table keeps three states apart: a figure that was published (including a published zero, which is a measurement), a metric that ran and published no row, and a metric this study never ran. On the bundled study that last one is the ECG count, which stops on the missing domain rather than reporting a zero. A blank cell in a census table is the defect this replaces; a line saying which metric produced no figure is not.

- **`SafetyCensus()` keeps its name and loses its arithmetic** ([#66](https://github.com/jwildfire/gsm.safety/issues/66)) — the function runs the census metrics over the domains it is given and reads what they published through the report's own helpers. Every number it returns is a `Numerator` a metric published, beside the `Denominator` that same metric published. There is one counting lane in this package now, and it is the metric; a figure that is wrong is wrong in exactly one place.
- **Two new domain arguments, `dfDeath` and `dfRandomization`** ([#66](https://github.com/jwildfire/gsm.safety/issues/66)) — the death count reads `gsm.mapping`'s `Mapped_Death`, which is its own union of the death domain and the study-completion domain's discontinuation reason, and the randomised count reads `Mapped_Randomization` rather than a treatment-arm column a blinded safety view should not read. Both are appended after the released arguments, so a positional call keeps its meaning.
- **The column arguments are deprecated and ignored, not removed** ([#66](https://github.com/jwildfire/gsm.safety/issues/66), D0023.5 approved) — `strArmCol`, `strTimeOnStudyCol`, `strTimeOnTreatmentCol`, `strLabVisitCol`, `strLabVisitNumCol`, `strECGVisitCol`, `strECGVisitNumCol`, `strCompleteCol`, `strReasonCol` and `chrDeathValues` still exist and passing one still runs; it warns, names what it named, and changes no figure. Every census metric declares the columns it reads in its own definition, so the function no longer takes a column name from its caller.
- **`strIDCol` still works, and `strGroupCol` is new** ([#66](https://github.com/jwildfire/gsm.safety/issues/66)) — a domain keyed on another participant column is renamed to the mapped-domain convention before the metrics read it. A subject domain with no study identifier still counts, with a warning: the identifier groups the metrics and never appears in what the function returns, so refusing to count without one would break a caller over a value it does not publish.
- **A test the rebuild can fail** ([#66](https://github.com/jwildfire/gsm.safety/issues/66)) — the fixtures behind `SafetyCensus()`'s suite are built so that the arithmetic the function used to do and the arithmetic the metrics do give different answers, and the tests assert the metric's answer. Beside them, a structural check reads the function's own body and every helper it calls and fails if an arithmetic operator or an aggregating function is named in any of them. A rebuild that left the counting in place and put a workflow beside it would pass the first kind by accident of agreement; it cannot pass the second.

- **The qualification records ship inside the package** ([#63](https://github.com/jwildfire/gsm.safety/issues/63)) — the three records behind this release moved from `design/` to `inst/qualification/`, so they travel with the thing they qualify. A reviewer reaches them from the installed package with `system.file("qualification", package = "gsm.safety")`, without the repository — and, the reason it matters most here, the checks that read them now run under `R CMD check`, which is the context the merge is gated on. `design/` is `.Rbuildignore`'d and absent from the built tarball, so those checks used to skip in exactly the place that decides whether the work lands.
- **Every qualification record is checked against the code, and the records against each other** ([#63](https://github.com/jwildfire/gsm.safety/issues/63)) — `death-count-qualification.md` and `census-metrics-qualification.md` had no document-agreement layer at all, and the report's own record was not checked by the file that checks the other two. All three are now: every figure in every table of every record is compared with the constants the suite asserts against the live pipeline, and a disagreement fails by name — *census-metrics-qualification.md records saf0013 route A: 77, expected 76* — instead of staying green. That is not hypothetical. The death record carried a wrong `SafetyCensus()` figure for a day and a person reading it caught it, not a test; that figure is now checked in both records, which have to agree with each other about it.
## Worth knowing

- **The bundled study moves, so the qualification is version-pinned.** Between gsm.core 1.2.0 and 1.3.1 the reference study changed under the same name: enrolled went from 760 to 762 and discontinuation-reason deaths from 1 to 4, taking the published count from 12 to 13. The qualification test always checks the identities that hold on any version — that the two routes agree, that the count is the union anchored to the enrolled population, that it exceeds the 1 the function reports — and pins the exact counts to the gsm.core version they were measured on. A different version skips those two assertions with the recorded and the live numbers both named. Re-qualifying a clinical count is a deliberate act, not a silent re-derivation.
- **`gsm.core::CheckSpec()` only warns on a missing column.** The design assumed a declared column that is missing would stop the workflow with an error, and called the false-zero defect fixed by construction. It errors on a missing *data.frame* but merely warns on a missing *column* — verified again against gsm.core 1.3.1. Declaring the columns is therefore necessary but not sufficient. Every census metric in this release checks its own columns and stops, through one shared guard rather than twelve copies of it.
- **Data completeness is not in this release, and that is a scope call rather than an oversight.** It is the one census figure whose inputs the design leaves open — "a declared input rather than an assumption" — and scoping it turned up two facts that have to be settled before it can be written. `Mapped_LB` under the standard mapping carries no visit column at all, and a metric's own `Mapped_*` spec does not propagate back into `Ingest()`'s column subsetting, so a coverage figure cannot key on a lab row's visit label even if it wanted to. And with "expected" answered as the participants whose time on study reaches a visit (D0023.2), the expected count needs a per-visit study day that neither `Mapped_VISIT` nor `Mapped_SUBJ` supplies. Both are definitional choices that belong with the coverage table in the report step, not guesses made here. Recorded in `inst/qualification/census-metrics-qualification.md`.
- **`saf0011` is written but cannot be measured on any study available today.** `gsm.mapping` ships no ECG mapping and the bundled study has no ECG records, so the ECG count has no second route to be checked against. What is checked is that it *stops* rather than publishing a zero when the domain is absent — the designed behaviour — and the suite asserts that no bundled ECG domain has appeared, so if one ever does the test fails and the metric gets measured rather than left passing.
- **On the bundled study, dosing cannot be told apart from enrolment.** `firstdosedate` is identical to `enrolldt` and to `firstparticipantdate` for all 762 enrolled participants, so `saf0007` and `saf0005` both read 762. The metric is right; the synthetic study simply does not exercise the difference. Worth knowing before anyone reads 762 as confirmation of the fix.
- **The documentation site's reference index was missing eight topics, and that is why its build has been failing.** pkgdown errors rather than warns on an exported topic no section lists, and the index had not kept up: both metric steps this release adds, the four already there, `Flag_None`, `SafetyCensus`, and the two widgets from the v1.7.0 adoption. The index now carries all of them, under a *Metric steps* section that says which metrics each step feeds and a *Study census* section that says the function is unchanged until step four. Verified by building the index locally, which now succeeds.
- **The bundled study's own figures were re-measured rather than quoted.** Everything D0023 says about this study was measured on gsm.core 1.2.0. Three of its figures did not survive re-measurement on 1.3.1, and one of step one's did not either: `SafetyCensus()` reports four deaths on this study, not one. All of them are recorded in `inst/qualification/census-metrics-qualification.md` with what changed and why.
- **Data coverage is absent from the report, and absent is not empty.** The thirteenth metric did not land, so no study supplies a coverage figure today and the report renders *without* a coverage section rather than with an empty coverage table. That is the point: an empty coverage table would read as a study with no data rather than as a report with no metric, which is the exact confusion a coverage figure exists to prevent. The workflow's settings name the coverage metric IDs to read and ship naming none, so the section appears the day a coverage metric does — checked in the suite from both directions.
- **Two things D0023 placed in the report are not in it, on purpose.** The design says the report would compute the median days on treatment from the exposure metric's per-participant table, and would build the breakdown of discontinuation reasons from free text. [#61](https://github.com/jwildfire/gsm.safety/issues/61) sets a harder bar than the design did — a number no metric produces is a missing metric, not a calculation to put in the report — and the bar wins, because a median computed in the report is a second counting lane whatever it is computed from. Neither figure is lost: the median wants an averaging step and the reason breakdown wants an enumeration the metric layer cannot express, and both are named here rather than quietly dropped. The blank-reason defect they were meant to fix was not fixed in step four either: it was removed with the free-text reason breakdown that carried it, which is under *What left the payload* below.
- **The bundled study has moved again, and the recorded figures are pinned behind it.** Every figure in this release was measured on gsm.core 1.3.1. gsm.core's `main` branch — which this package's `Remotes` track — now carries 1.3.1.9000, and its bundled `AA-AA-000-0000` is a different study again: 758 enrolled rather than 762, 12 deaths rather than 13, and 682 dosed against 758 enrolled rather than 762 against 762. The metrics are unaffected; what is affected is the snapshot the qualification tests assert, which skips on any version but the one it was measured on and therefore skips on `main` today. Re-qualifying is a deliberate act by a person, so the recorded figures stay as measured and the drift is stated here instead. One consequence worth having: on the newer study, dosing and enrolment finally differ, so `saf0007` and `saf0005` can be told apart on the reference study for the first time.
- **The payload's shape is a contract, and four of its labels are part of it.** The demo application picks `Enrolled participants`, `Received study drug`, `Person-years on treatment` and `Deaths` out of this payload by exact string and drops a tile silently rather than erroring if one is reworded (D0023.5). They are unchanged word for word, with a test behind them, and so are the three tables, their columns, and the `Census`/`Exposure`/`Follow-up` groups the application filters by.
- **Two figures deliberately carry no denominator, because their reader turns one into a percentage.** Every census metric publishes a denominator and the report shows it in a labelled column. This payload has no such column: `73.2 person-years of 762 (10%)` is what carrying it through would produce. So the enrolled count and the two person-time figures carry none, exactly as before, and every other figure carries the denominator its own metric published.
- **`SafetyCensus()` now calls `gsm.core::RunWorkflow()`, which gsm.core soft-deprecated in 1.3.0** in favour of `workr::RunWorkflow()`. The call works and the deprecation warns once per session; taking a dependency on `workr` is an ecosystem-wide move rather than one this release should make on its own, and it is named here rather than left to surface as a surprise.
- **`yaml` moved from Suggests to Imports.** The function reads the metric definitions and the report's settings from the installed workflow files at run time, which is what stops the labels, the sections and the days-per-year division from being written down twice. `yaml` is already a hard dependency of `gsm.core`, so nothing new is installed.

- **A green check is not evidence that a check ran.** The three document-agreement checks skipped for the whole of step three, and the run was green: the skip was one line inside a list of sixteen. Two things guard the repeat. `tests/testthat/test-qualification-records.R` fails — never skips — if a record stops shipping with the package or if one appears that nothing reads, so adding a record means adding its check. And every document-agreement block prints a `[QUALIFICATION]` line naming the record and how many figures it compared, which lands in the test output `R CMD check` writes and CI prints. Absence from a skip list is not proof that a check ran; a line in the log is.
- **Un-ignoring `design/` would not have fixed this, and that was measured rather than argued.** Building the package with `^design$` removed from `.Rbuildignore` does put `design/` into the tarball — and the three checks still skip. `R CMD check` runs the suite from `<pkg>.Rcheck/tests/testthat`, where the records' relative path resolves to `<pkg>.Rcheck/design`; the unpacked source lands at `<pkg>.Rcheck/00_pkg_src/gsm.safety/design` instead, and nothing looks there. Installed content under `inst/` is reachable through `system.file()` in every context the suite runs in; repository content beside the package is reachable in none of them.
- **Nothing upstream changed, and the flagging metrics did not move.** The three flagging `saf000*` metrics are untouched and the twelve new rows land beside them through the ordinary `Analyze` → `Summarize` chain. `SafetyCensus()` resolves, keeps every argument it had in the order it had them, and returns the same three tables with the same columns — what changed is the numbers in them, and they are named at the top of these notes.

# gsm.safety v1.1.0

**See it move:** the [annotated v1.1 demo](https://jwildfire.github.io/obot.roadmap/reports/gs-v1.1-demo/) walks the new metrics running live on the [DEMO-301 study site](https://jwildfire.github.io/demo-301/#/safety), with captures and try-it-yourself steps.

gsm.safety could draw the eDISH chart but could not tell you how many participants were in the Hy's Law quadrant. This release adds the metrics phase that answers that — three participant-level safety metrics plus the denominators a safety overview leads with — and moves the report workflows into the standard gsm phase layout on the way. One path changes: workflows formerly under `inst/workflow/3_reports/` now live in `inst/workflow/4_modules/`.

## What's new

- **A `2_metrics` workflow phase: three participant-level safety metrics** ([#45](https://github.com/jwildfire/gsm.safety/issues/45), PR [#47](https://github.com/jwildfire/gsm.safety/pull/47); hub [obot.roadmap#138](https://github.com/jwildfire/obot.roadmap/issues/138)). `saf0001` Hy's Law candidate, `saf0002` QTcF prolongation, and `saf0003` serious / related AE — each scores one row per participant with an ordinal tier through the standard gsm contract (`Analyze_Identity()` + `Flag()`, following gsm.kri's `pat0015` precedent), so subject-level rows land in `Reporting_Results` beside site and country rows with nothing downstream changing. The liver and QT cut-points come from the vendored data contracts of the charts they correspond to, so the metric and the chart cannot drift apart. Measured on demo data before being treated as real (the hub#138 gate): 9 / 11 / 68 red-tier participants of 765 scored. [See them live](https://jwildfire.github.io/demo-301/#/safety/metric/saf0001).
- **`SafetyCensus()`** (PR [#47](https://github.com/jwildfire/gsm.safety/pull/47)) — reduces the mapped domains to the denominators a safety overview leads with: enrollment, exposure, person-years, deaths, and **data coverage per visit** — the figure that decides whether a quiet visit is reassuring or empty. New exported helpers behind the metrics: `Input_HysLaw()`, `Input_QtProlongation()`, `Input_SafetyAE()`.
- **Report workflows move to `inst/workflow/4_modules/`** ([#46](https://github.com/jwildfire/gsm.safety/issues/46), PR [#47](https://github.com/jwildfire/gsm.safety/pull/47); hub [obot.roadmap#136](https://github.com/jwildfire/obot.roadmap/issues/136)) — the standard gsm phase directory for `meta.Type: Report` workflows, the one gsm.kri already uses. Update any pipeline that globbed `3_reports/`.
